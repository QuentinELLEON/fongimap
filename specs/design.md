# FongiMap — Design Document

**Version:** 1.0  
**Last updated:** November 2026

---

## 1. System Overview

FongiMap is a two-file static web application. No server is involved at any stage of usage.

```
fongimap/
├── index.html     ← All UI, logic, libraries, and basemap GeoJSON inlined
└── data.js        ← Generated by build.py; sets window.FMAP_META + window.FMAP_DATA
```

The build pipeline is a separate concern — it runs once offline by the developer/user after obtaining the raw CSV. The outputs (`index.html` and `data.js`) are then distributed together.

## 2. Data Pipeline Design

### 2.1 Source

- File: `DATA_Gautier et al 2022.csv`
- Size: 219.3 MB
- Encoding: UTF-8 with BOM
- Separator: comma
- Rows: 1,043,262

### 2.2 Binary Record Format

Each record is packed into **18 bytes** (little-endian) using a fixed-width format. No per-record allocation at read time — the browser reads directly from a flat `Uint8Array` using byte offsets.

```
Offset  Bytes  JS type      Field             Notes
──────  ─────  ──────────   ────────────────  ──────────────────────────────────────
0       2      Uint16       lon_q             Quantised longitude. 0xFFFF = missing.
2       2      Uint16       lat_q             Quantised latitude.  0xFFFF = missing.
4       2      Uint16       year              Calendar year. 0 = missing.
6       1      Uint8        month             1–12. 0 = missing.
7       2      Uint16       species_idx       Index into dicts.species[]. 0xFFFE = missing.
9       1      Uint8        family_idx        Index into dicts.family[].  0xFF = missing.
10      1      Uint8        order_idx         Index into dicts.order[].   0xFF = missing.
11      1      Uint8        class_idx         Index into dicts.class_[].  0xFF = missing.
12      1      Uint8        phylum_idx        Index into dicts.phylum[].  0xFF = missing.
13      1      Uint8        guild_idx         Index into dicts.guild[].   0xFF = missing.
14      1      Uint8        trophic_idx       Index into dicts.trophic[]. 0xFF = missing.
15      1      Uint8        dept_idx          Index into dicts.dept[].    0xFF = missing.
16      1      Uint8        ecoregion_idx     Index into dicts.ecoregion[].0xFF = missing.
17      1      Uint8        corine_idx        Index into dicts.corine[].  0xFF = missing.
──────  ─────
Total   18 bytes per record
```

**Coordinate quantisation:**

```
lon_q = round((lon - LON_MIN) / (LON_MAX - LON_MIN) × 65534)
lat_q = round((lat - LAT_MIN) / (LAT_MAX - LAT_MIN) × 65534)

France bbox:  lat [41.0, 51.5]   lon [−5.5, 10.0]
Resolution:   lat ≈ 1.6m   lon ≈ 2.3m   (at 65534 steps over ~10° / ~15°)
```

**Dictionary encoding:**

String fields are replaced by an integer index into a sorted-by-frequency array stored in `FMAP_META.dicts`. The encoder takes the top-N most frequent values; any value not in the top-N gets index 0xFF (treated as missing). This allows the browser to do fast integer comparisons during filtering.

| Field | Index type | Max unique values |
|---|---|---|
| species | uint16 | 65,534 |
| family | uint8 | 254 |
| order | uint8 | 254 |
| class | uint8 | 254 |
| phylum | uint8 | 254 |
| guild | uint8 | 254 |
| trophic_mode | uint8 | 254 |
| department | uint8 | 254 |
| ecoregion | uint8 | 254 |
| CORINE_biotope | uint8 | 254 |

```js
  "record_size": 18,

  "lon_min": -5.5,  "lon_max": 10.0,
  "dicts": {
    "species":   ["Agaricus bisporus", "Boletus edulis", ...],
    "family":    ["Agaricaceae", ...],
    "order":     ["Agaricales", ...],
    "class_":    ["Agaricomycetes", ...],
    "phylum":    ["Basidiomycota", "Ascomycota", ...],
    "guild":     ["Mycorrhizal", "Litter Saprotroph", ...],
    "trophic":   ["Symbiotroph", "Saprotroph", ...],
    "dept":      ["Pas-de-Calais", "Doubs", ...],
    "ecoregion": ["Atlantic", "Continental", "Mediterranean", "Montane"],
    "corine":    ["41.1", "41.2", ...]
  }
};

window.FMAP_DATA = '<base64-encoded zlib-compressed binary>';
```

### 2.4 Expected sizes

| Stage | Size |
|---|---|
| Raw CSV | 219.3 MB |
| Packed binary (18 B × 1,043,262) | ~18.8 MB |
| After zlib level-9 compression | ~5–7 MB (estimated 3× ratio) |
| After base64 encoding | ~7–9 MB |
| `data.js` on disk | ~7–9 MB |

### 2.5 `build.py` flags

| Flag | Default | Description |
|---|---|---|
| `--csv PATH` | auto-detected | Path to source CSV |
| `--out DIR` | script directory | Output directory for `data.js` |
| `--sample N` | 0 (all rows) | Process only N rows for testing |
| `--inspect` | off | Print schema/stats and exit without writing output |

## 3. Frontend Architecture

### 3.1 Inlined Dependencies

All code and data is inlined into `index.html` at build time by `assemble_html.py`.

| Resource | Version | Size | Role |
|---|---|---|---|
| fflate UMD | 0.8.2 | 32 KB | zlib decompression in-browser |
| D3.js | 7.9.0 | 280 KB | SVG rendering, projections, scales, zoom |
| Départements GeoJSON | — | ~569 KB | 96 département polygons |
| Regions GeoJSON | — | ~225 KB | 13 region boundary overlays |
| App CSS | — | ~8 KB | All styles |
| App JS | — | ~25 KB estimated | All application logic |

Total `index.html` estimated size: **~1.1 MB**

### 3.2 Startup Sequence

```
1. Browser parses index.html
2. Inline <script> tags execute:
   a. fflate loaded → window.fflate available
   b. D3 loaded → window.d3 available
   c. window.FMAP_DEPTS and window.FMAP_REGIONS set (GeoJSON)
3. data.js <script> tag executes → window.FMAP_META and window.FMAP_DATA set
4. App IIFE runs:
   a. Show loading overlay
   b. atob(FMAP_DATA) → Uint8Array (base64 decode)
   c. fflate.decompressSync() → raw binary buffer
   d. Create 14 typed-array column views from buffer
   e. Build reverse-lookup maps (dept code → dept idx, etc.)
   f. Render basemap SVG (D3 projection + GeoJSON paths)
   g. Run initial filter pass (no filters → all records pass)
   h. Render all charts with full data
   i. Populate sidebar chips and lists from metadata
   j. Hide loading overlay, enable interactivity
```

### 3.3 Data Model in the Browser

After parsing, the app holds data as a set of flat typed arrays — one per field. This avoids per-record object overhead and enables fast vectorised filtering.

```js
// Each array has length = n_records (1,043,262)
columns = {
  lon_q:     Uint16Array,   // quantised longitude
  lat_q:     Uint16Array,   // quantised latitude
  year:      Uint16Array,
  month:     Uint8Array,
  species:   Uint16Array,
  family:    Uint8Array,
  order:     Uint8Array,
  class_:    Uint8Array,
  phylum:    Uint8Array,
  guild:     Uint8Array,
  trophic:   Uint8Array,
  dept:      Uint8Array,
  ecoregion: Uint8Array,
  corine:    Uint8Array,
}
```

Memory: 18 B × 1,043,262 ≈ **18.8 MB** for the raw buffer + ~19 MB for the typed array views = **~38 MB** total. Well within browser limits.

### 3.4 Filter & Render Loop

```
User interaction
  → update state object
  → applyFilters()        // single pass over all records, builds Uint8Array mask
  → updateStats()         // count filtered records, unique species, unique depts
  → updateMap()           // recolor département choropleth
  → updateDots()          // resample & reposition dot layer (if visible)
  → updateHexbin()        // rebin hex cells (if visible)
  → updateTimeline()      // recount by year
  → updateMonthChart()    // recount by month
  → updatePhylumChart()   // recount by phylum
  → updateGuildChart()    // recount by guild
  → updateTopSpecies()    // top-15 by count
  → updateTopFamilies()   // top-10 by count
```

**Filter mask computation (performance-critical path):**

```
mask = new Uint8Array(n_records)  // 1 byte per record = ~1 MB

for i in 0..n_records:
  mask[i] = (
    matchesSpecies(i) &&
    matchesPhylum(i)  &&
    matchesGuild(i)   &&
    matchesTrophic(i) &&
    matchesEcoregion(i) &&
    matchesYear(i)    &&
    matchesMonth(i)   &&
    matchesDept(i)
  ) ? 1 : 0
```

Each `matches*` function does a single integer comparison or Set.has() lookup. Target: <100ms for the full loop on a 2020 laptop.

### 3.5 Filter State Object

```js
const state = {
  speciesIdx:   null,      // uint16 or null
  phylumSet:    new Set(), // uint8 values; empty = all pass
  guildSet:     new Set(),
  trophicSet:   new Set(),
  ecoregionSet: new Set(),
  yearMin:      0,         // 0 = disabled
  yearMax:      0,         // 0 = disabled
  monthSet:     new Set(), // 1–12; empty = all pass
  deptSet:      new Set(), // uint8 values; empty = all pass
}
```

### 4.2 Panel Descriptions

#### Topbar
- Left: logo (🍄) + app title + subtitle
- Centre: three stat pills — filtered record count, unique taxa, departments with records
- Right: GPS dots toggle, hexbin toggle, reset button

#### Sidebar (230px, scrollable)
- Taxon search input with dropdown autocomplete
- Phylum chips (Basidiomycota, Ascomycota, + others grouped)
- Guild chips (top 10 guilds)
- Trophic mode chips
- Ecoregion chips (Atlantic / Continental / Mediterranean / Montane — exactly 4)
- Year range slider (dual-thumb, 1900–2021)
- Month grid (3 columns × 4 rows, Jan–Dec)
- Département multi-select list

#### Map Panel
- Fills all available space between topbar and chart rows
- Minimum height: 300px
- Projection: `d3.geoConicConformal().rotate([-2.5, 0]).parallels([44, 49])` centred on France
- Choropleth: YlGn 9-class sequential scale, domain = [0, max_dept_count]
- Department click → add to dept filter (second click removes)
- Hover tooltip (floats near cursor):
  - Département name + code
  - N records (N% of total filtered)
  - Top 3 species
  - Dominant guild
- Zoom buttons: +, −, ⊞ (reset to fit-France)
- Legend: colour scale with 3 labelled breakpoints

#### Timeline chart (140px tall)
- Bar chart, X = year, Y = count
- D3 brush for range selection → sets year filter
- Bars highlighted in accent colour for years within the year filter

#### Monthly distribution chart (140px tall)
- Bar chart, Jan–Dec on X
- Click bar → toggle month filter
- Active months highlighted

#### Phylum donut (180px)
- Segments: Basidiomycota, Ascomycota, "Autres"
- Click segment → toggle phylum filter
- Percentage labels on segments > 5%

#### Guild donut (180px)
- Top 9 guilds + "Autres" segment
- Click segment → toggle guild filter

#### Top-15 species bar chart (180px)
- Horizontal bars, sorted descending by count
- Species name on Y axis (truncated at 25 chars)
- Click bar → set species filter

#### Top-10 families bar chart (180px)
- Same style as top species

## 6. File & Module Structure

```
fongimap/
├── index.html              ← Final deliverable (assembled by assemble_html.py)
├── data.js                 ← Generated by build.py (user runs after getting CSV)
│
├── build.py                ← ETL: CSV → data.js
├── assemble_html.py        ← Assembles index.html from src/ + build/ + data_processed/
│
├── specs/
│   ├── context.md          ← Session history and decisions (this session)
│   ├── requirements.md     ← Functional & non-functional requirements
│   ├── design.md           ← This file
│   └── tasks.md            ← Ordered implementation tasks
│
├── src/
│   ├── style.css           ← All CSS
│   └── app.js              ← All JS application logic (single IIFE)
│
├── build/
│   ├── d3.min.js           ← D3 v7.9.0 minified (downloaded, 280 KB)
│   └── fflate.umd.js       ← fflate v0.8.2 UMD (downloaded, 32 KB)

└── data_processed/
    ├── departements.geojson  ← 96 département polygons (simplified, 569 KB)
    └── regions.geojson       ← 13 region boundaries (simplified, 225 KB)
```

`data_raw/` is where the user places the raw CSV before running `build.py`. It is gitignored (219 MB).

## 7. Open Design Questions

These need a decision before implementation begins:

| # | Question | Default assumption |
|---|---|---|
| 1 | Dot layer downsampling: random subsample vs. spatially stratified (one per hex cell at zoom)? | Random subsample to 100k |
| 2 | Choropleth metric: raw count vs. records/km²? | Raw count (simpler); toggle as future improvement |
| 3 | Default year range: 1900–2021 or full 1708–2021? | 1900–2021 shown by default; slider min set to 1900 |
| 4 | Corsica: in main viewport vs. separate inset? | In main viewport (GeoJSON includes 2A + 2B) |
| 5 | CORINE biotope filter: include with coverage warning vs. exclude? | Include but note 11.8% coverage |
| 6 | Mobile layout: responsive vs. desktop-only? | Desktop-only (min 1280px) for now |
